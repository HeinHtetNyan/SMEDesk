# SMEDesk — project notes

POS + accounting + inventory for small/medium businesses. See `README.md` for the stack overview and per-project local setup. This file is operational notes for working in the codebase — things that aren't obvious from reading the code once.

## Layout

```
SMEDesk/
  backend/     FastAPI + SQLAlchemy (async) + Alembic. The only layer with real logic so far.
  frontend/    Vite + React + TS. Shared UI, built once, wrapped by desktop/mobile.
  desktop/     Tauri shell around frontend/dist. Rust, compiles clean (cargo check verified).
  mobile/      Capacitor shell around frontend/dist, + native android/ project (tracked in git).
```

`desktop/` and `mobile/` contain no app UI of their own — they build `frontend/` and wrap the static output. Day-to-day UI work happens in `frontend/`.

## Backend

- Entry point `app/main.py`; routes live under `app/api/`, models under `app/models/`, Pydantic schemas under `app/schemas/`.
- Auth is the only implemented domain: signup, login, `/me`. JWT via `python-jose`, password hashing via **raw `bcrypt`** (not `passlib` — see Gotchas below).
- `UserRole` (`app/models/user.py`) is a `str, enum.Enum`. SQLAlchemy's `Enum(UserRole, ...)` stores the Python member **names** (`OWNER`, `MANAGER`, ...) in Postgres, not the lowercase `.value`s. This is consistent end-to-end (creation and inserts both use `.name`), so it isn't a bug — just don't assume the DB enum labels match `UserRole.OWNER.value`.
- Multi-tenant: every business-scoped table carries `business_id`; UUID primary keys throughout (`app/models/base.py`) so offline-created records never collide on sync once PowerSync lands.

### Local setup

```bash
cd backend
python -m venv venv && ./venv/Scripts/activate
pip install -r requirements-dev.txt   # includes requirements.txt + pytest
cp .env.example .env                  # fill in DATABASE_URL / JWT_SECRET
alembic upgrade head
uvicorn app.main:app --reload
```

Needs a reachable Postgres matching `DATABASE_URL`. Locally that's a `postgresql-x64-17` Windows service with a `smedesk`/`smedesk` role+db (see `.env.example`) — default superuser password from the winget EDB package is `postgres`.

### Tests

```bash
cd backend
pip install -r requirements-dev.txt
# create a `smedesk_test` Postgres db first (owned by the smedesk role) — tests wipe/rebuild its schema each run
python -m pytest tests/ -v
```

`tests/conftest.py` points `DATABASE_URL` at `smedesk_test` before any `app.*` import (the engine is built at import time, so this must happen first), creates tables via `Base.metadata.create_all`, and truncates `users`/`businesses` before every test. All async fixtures and tests share one event loop (`asyncio_default_fixture_loop_scope = session` / `asyncio_default_test_loop_scope = session` in `pytest.ini`) — without that, the session-scoped engine and function-scoped tests fight over event loops and every test errors with `cannot perform operation: another operation is in progress`.

## Frontend

- `npm run build` = `tsc -b && vite build`. Both `tsc -b` and `oxlint` are clean.
- The "Industry" design system lives in `src/styles/industry.css` — plain CSS, no build step, documented inline. `Blueprint.tsx` / `Corners()` implement the wireframe corner-mark motif used throughout.
- No routing/state library yet — `App.tsx` just swaps a `Dashboard` component in/out via local `useState`. Not wired to the backend at all yet (no fetch calls anywhere in `frontend/src`).

## Desktop (Tauri)

- `desktop/src-tauri` — standard `tauri init` scaffold, unmodified beyond icons/identifier. `cargo check` compiles clean with no warnings.
- `identifier: com.smedesk.app` in `tauri.conf.json` matches the Android `applicationId`.

## Mobile (Capacitor)

- **Requires JDK 21** to build (`@capacitor/android` 8.5's own `build.gradle` sets `sourceCompatibility JavaVersion.VERSION_21`). A JDK-17-only machine fails `./gradlew assembleDebug` with `error: invalid source release: 21` at `:capacitor-android:compileDebugJavaWithJavac`. Confirmed both ways on this machine: fails on JDK 17 only, `BUILD SUCCESSFUL` (`app-debug.apk` produced) once Temurin 21 is installed alongside the existing JDK 17 and `JAVA_HOME` points at it for the Gradle invocation. No project file changes needed — just point `JAVA_HOME` at a JDK 21 when building, e.g. `JAVA_HOME="/c/Program Files/Eclipse Adoptium/jdk-21.x.x.x-hotspot" ./gradlew assembleDebug`.
- `mobile/android/app/src/main/assets/public` (the built web bundle) is gitignored and regenerated by `npm run sync`; don't hand-edit it.
- `colorPrimary`/`colorPrimaryDark`/`colorAccent` referenced in `res/values/styles.xml` aren't defined in this project's own `colors.xml` — they come from the `@capacitor/android` library module's resources, merged in at build time. Looks like a dangling reference at first glance; it isn't.
- `npm audit` flags a moderate `uuid` vuln via `xcode ← @capacitor/cli` (iOS project tooling, unused on this Android-only project, dev-only). `npm audit fix --force` would downgrade `@capacitor/cli` below the `^8.5.0` pinned for `@capacitor/android`/`@capacitor/core` — left alone deliberately rather than risk a version-mismatch bug for a near-zero real-world risk.

## Things fixed here worth knowing about

- **`passlib[bcrypt]` was completely broken** — `passlib` 1.7.4 reads `bcrypt.__about__`, which `bcrypt` ≥4.1 no longer exposes, so every signup/login call 500'd. Replaced with `bcrypt` used directly in `app/core/security.py`. If you ever see `AttributeError: module 'bcrypt' has no attribute '__about__'`, this is why — don't reintroduce `passlib`.
- The initial Alembic migration didn't exist until this pass (`alembic/versions/d6e036b06d61_initial_schema.py`) — autogenerated, then hand-patched: `downgrade()` dropped the tables but not the `user_role` Postgres enum type, so `downgrade` → `upgrade` failed with `type "user_role" already exists`. The fix (`sa.Enum(name='user_role').drop(op.get_bind(), checkfirst=True)` at the end of `downgrade()`) is now baked into that migration file — remember the same gotcha applies to any *future* migration that adds a new native enum column.
- `login()` used to only check the password, not `is_active` — a deactivated user could still be handed a valid JWT (it would just fail on the next authenticated call). Fixed to reject at login.
- Signup/login previously had no password length bounds — empty passwords were accepted, and anything over bcrypt's 72-byte cap 500'd instead of returning a clean validation error. Both are now `Field(min_length=..., max_length=72)` on the Pydantic schemas.
